How this is built

The demo mirrors the platform, it does not replace it.

Every number in the panels above either comes from the published evaluation or is computed from the simulated window. The platform itself runs against real Zeek logs in the repository.

  • 1CaptureZeek conn.log (TSV or JSON) from a live interface or replay
  • 2Ingestreader.py — offset-persisted tailing, rotation and truncation handling
  • 3Features23-feature extractor shared by training and inference
  • 4DetectHistGradientBoosting @ 0.95 threshold + 10 rule detectors
  • 5PersistSQLite — events, predictions, alerts, ingestion state, dead letters
  • 6ServeFastAPI REST + WebSocket fan-out, authenticated sensor ingestion
  • 7ObserveReact 19 dashboard — live stream, analytics, model and sensor health

Where it fails

  • Metadata-only detection: flow features, no payload inspection.
  • Cross-dataset transfer is weak; the model is a decision-support tool, not an unattended production sensor.
  • SQLite storage is single-node, and authentication is opt-in rather than enforced by default.
  • Detector thresholds are heuristic and need per-site tuning.
